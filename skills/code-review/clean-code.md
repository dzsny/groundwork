# Clean-code pass — the judgment remainder

Static checkers catch what static checkers catch. These are the rules that need a reader. Each
is **pass**, **justified exception**, or **fail**; *soft* rules admit an exception with a stated
reason, the rest are hard fails.

**Scope reminder: the gate judges the diff.** A pre-existing violation in a file this PR barely
touches is out of scope, and saying so is part of the job.

## Naming and intent

| Rule | Hard/soft | What a failure looks like |
| --- | --- | --- |
| A name states what the thing *is* or *does*, in the domain's words | hard | `data2`, `handleStuff`, `TempManager`, `utils.py` growing a tenth unrelated function |
| No abbreviation that is not already the domain's own | soft | `usr`, `cfgMgr`, `calcAmt` |
| Booleans read as assertions | soft | `flag`, `check` → `is_expired`, `has_permission` |
| The name does not lie | hard | `get_user()` that creates a user; `validate()` that mutates |

## Structure

| Rule | Hard/soft | What a failure looks like |
| --- | --- | --- |
| A function does one thing at one level of abstraction | soft | A handler that parses, validates, computes, persists and formats inline |
| Nesting stays shallow — guard clauses over pyramids | soft | Four levels of `if` where three are error paths |
| No parameter that exists only to select behavior | soft | `process(x, mode="a")` with two disjoint bodies |
| Module boundaries match the directory structure | hard | `domain/` importing from `web/` |
| No cyclic imports between modules | hard | — |

## Error handling — "raise, don't bury"

| Rule | Hard/soft | What a failure looks like |
| --- | --- | --- |
| **Fail fast; no bug-hiding fallback** | hard | `except Exception: return None`; a default that masks a missing config; a retry that swallows a permanent error |
| Errors carry the context needed to act | hard | `raise ValueError("invalid")` with no value, field or source |
| Caught exceptions are either handled or re-raised, never logged-and-continued | hard | `log.error(e)` followed by normal flow |
| External failures have an explicit policy | hard | An outbound call with no timeout; a retry with no cap or backoff |
| No empty `except` / `catch` | hard | — |

This is the cluster worth being strictest about. A swallowed error is a bug that will be
diagnosed months later, by someone else, from a symptom three layers away.

## Complexity

| Rule | Hard/soft | What a failure looks like |
| --- | --- | --- |
| **Simple is measured from the reader's seat** | soft | A clever one-liner nobody can modify; a metaclass where a function would do |
| No speculative generality | hard | An interface with one implementation "for later"; a plugin system for two cases; config for a value that has never changed |
| No duplicated *knowledge* | soft | The same business rule encoded in three places. Duplicated *code* that encodes different knowledge is fine — do not merge it |
| Dead code is deleted, not commented out | hard | — |

## Comments and documentation

| Rule | Hard/soft | What a failure looks like |
| --- | --- | --- |
| Comments explain **why**, never what | soft | `# increment i` |
| No stale comment contradicting the code | hard | — |
| Every new `TODO` carries a ticket id | hard | `# TODO: fix this properly` |
| Public API has a docstring stating contract, not restating the signature | soft | — |
| **Design pages update in the same PR as the behavior they describe** | hard | — |

## Agent residue

Specific to AI-assisted work, and worth checking every time:

| Rule | Hard/soft | What a failure looks like |
| --- | --- | --- |
| No AI attribution in code, comments or commit messages | hard | "Generated by…", "As an AI…" |
| No explanatory scaffolding left in the code | hard | `# Step 1: …` narrating an obvious sequence; a comment addressing the reader |
| No invented API | hard | A call to a method that does not exist in the installed version of the library |
| No unrequested defensive layer | soft | Try/except around code that cannot raise; validation of a value the type system guarantees |
| No plausible-but-unverified constant | hard | A magic timeout, threshold or URL that matches nothing in the config or the spec |
| Imports are all used and all real | hard | — |

## Tests

| Rule | Hard/soft | What a failure looks like |
| --- | --- | --- |
| Tests assert **behavior**, not implementation | hard | Asserting a private method was called; asserting a mock against itself |
| No tautological assertion | hard | `assert result == result`; `assert True` |
| No assertion-free test | hard | A test that only executes code, inflating coverage |
| Each test's name states the behavior and condition | soft | `test_1`, `test_works` |
| At least one failure mode per behavior | hard | Happy path only |
| No test that depends on another test's side effects, or on wall-clock time | hard | — |

## Security-adjacent (the full pass is `security.md`)

| Rule | Hard/soft | What a failure looks like |
| --- | --- | --- |
| No secret, key, token or credential in the diff | hard | Including in tests and fixtures |
| No personal data in logs or error messages | hard | — |
| External input is validated at the boundary | hard | — |
